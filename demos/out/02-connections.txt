## why the demos do not POST /api/connections for Pagila on the live engine
1. UI connections shadow CONNECTION_STRINGS for SQL execution (auto_ontology/connectors/registry.py get_connectors:
   env strings are read only when no UI connection exists), and the structured connection form has no
   SQLite type (connection_string_factory.py), so adding Pagila would take Chinook away from the engine.
2. DELETE /api/connections/{db} also asks the ingestion service to reset that database's catalog
   (service.delete_connection -> trigger_reset -> /ingest/delete), so undoing it would delete Pagila's
   hand-authored semantic layer from ao-catalog.
3. Without Vault the password would be stored in plaintext on the catalog row, i.e. in the graph.
NOTE: the ingestion service reads the other precedence (CONNECTION_STRINGS first, ingestion_service/connections.py), so the two services can disagree about which sources exist

Instead the Pagila questions run on a side engine (http://127.0.0.1:3011, demos/lib/side-engine.sh): the same code and the same
graph, with CONNECTION_STRINGS naming both Pagila and Chinook.
